# Team Assistant — Sprint 9

The PlanCraft Teams assistant exposes a single entry point for natural-language requests across tasks, meetings, chats, and vault insights. It runs behind an org-level feature flag (`settings.assistantEnabled`) and falls back to safe, deterministic behaviour when OpenAI credentials are absent.

## API surface

| Method | Endpoint | Description |
| --- | --- | --- |
| `POST` | `/api/orgs/:orgId/assistant/test-intent` | Parse a free-form prompt and return the detected intent + payload. |
| `POST` | `/api/orgs/:orgId/assistant/run` | Execute the detected intent, emit vault/feed updates, and return an assistant reply (text + optional TTS). |

### Request body (run)

```json
{
  "text": "Mark the onboarding checklist task complete",
  "speak": false,
  "voiceId": "optional-elevenlabs-voice-id"
}
```

### Response

```json
{
  "intent": { "intent": "update_task", "data": { "title": "Onboarding checklist" } },
  "action": { "ok": true, "type": "update_task", "message": "Updated task \"Onboarding checklist\"." },
  "response": "Done! Onboarding checklist is now marked complete.",
  "speech": "data:audio/mpeg;base64,...", // when ElevenLabs configured & `speak: true`
  "latencyMs": 940,
  "durationMs": 963,
  "requestId": "b2e54d2a-…",
  "context": { "tasks": 5, "meetings": 2, "chats": 3 }
}
```

Errors are returned with standard JSON bodies `{ "error": string }` and HTTP codes (400 invalid input, 403 feature disabled, 429 rate limit, 500 server errors).

## Intent → action map

| Intent | Behaviour |
| --- | --- |
| `create_task` | Creates a task (`source: assistant`) in `orgs/{orgId}/tasks`, records a vault entry (`type: assistant`), and returns a confirmation. |
| `update_task` | Looks up the latest task matching the provided title, applies status/progress/note updates, and records a vault entry. |
| `get_tasks` | Summarises the most recent tasks (status + assignees) using cached context. |
| `get_status` | Combines task and meeting highlights into a status digest (no write). |
| `unknown` | Falls back to contextual summary (and invokes OpenAI for a natural reply when configured). |

Vault entries generated by the assistant appear immediately in the Org Feed UI. Each entry includes metadata such as `taskId`, `status`, and `assignees`, enabling downstream analytics.

## Context aggregation

`buildAssistantContext` collects:

- Latest `tasks` (ordered by `updatedAt`, max configurable via `ASSISTANT_TASK_CONTEXT_LIMIT`)
- Latest `meetings` with summaries
- `vault` chat insights (`type == "chat"`)
- Optional semantic matches via `searchVault(query)`

The aggregated summary feeds both the OpenAI prompt (when available) and fallback responses.

## Rate limits & guardrails

- In-memory limiter on `/assistant/*` (default: `60_000ms` window / `30` requests).
- Org scope enforced by `withOrgAuth` and feature flag check (`settings.assistantEnabled` or `ASSISTANT_FEATURE_DEFAULT`).
- Structured logs written per request under the `assistant.intent` / `assistant.run` events, carrying `requestId`, `orgId`, `uid`, `intent`, and duration.

## Environment variables

| Variable | Description | Default |
| --- | --- | --- |
| `ASSISTANT_FEATURE_DEFAULT` | Global fallback when org settings don’t specify `assistantEnabled`. | `false` |
| `ASSISTANT_RATE_LIMIT_WINDOW_MS` | Rate limit window for `/assistant/*`. | `60000` |
| `ASSISTANT_RATE_LIMIT_MAX` | Max requests per window per user. | `30` |
| `OPENAI_ASSISTANT_MODEL` / `ASSISTANT_MODEL` | Override assistant response model. | `gpt-4o-mini` |
| `ASSISTANT_TASK_CONTEXT_LIMIT` | Number of tasks to include in context. | `5` |
| `ASSISTANT_MEETING_CONTEXT_LIMIT` | Meetings to include. | `3` |
| `ASSISTANT_CHAT_CONTEXT_LIMIT` | Chat insights to include. | `5` |
| `ELEVENLABS_VOICE_ID` | Optional default voice for `speech` payloads. | `null` |
| `ASSISTANT_SPEECH_VOLUME` | Normalized playback volume sent to the client (0 → 1). | `0.8` |
| `VOICE_INPUT_GAIN` | Gain applied to transcripts before task extraction. | `0.85` |

## Frontend usage

- `AskTeamsBar.vue` embeds in `TeamLayout` for always-on input.
- `assistantStore.ts` manages history, loading, and API calls.
- Responses update the Org Feed store automatically (`feedStore.fetchFeed(orgId, { reset: true })`), ensuring the sidebar feed reflects assistant actions within seconds.
- Speech playback uses the data URL returned by the API when TTS is enabled.

## QA checklist

1. Feature toggled off → `/assistant/run` returns 403.
2. Create task command → task appears in Task list + Vault/Feed within 3 seconds.
3. Update task command → status reflected in Task UI and new assistant vault entry visible.
4. Vault search question → assistant reply summarises relevant vault entries.
5. Rate limit reached → API returns 429 with `Retry-After` header.
6. Logs include `assistant.run` with `requestId` and duration.
